# Security and publication

This is a static portfolio scaffold without campaign execution, outbound delivery, tracking, credential collection or public deployment configuration.

Keep real recipients, event exports, approvals, domains, infrastructure identifiers, credentials and organization branding out of commits, issues, pull requests and screenshots. A real exercise requires approved scope and a separate private implementation.

Use GitHub private vulnerability reporting if available. Otherwise use the professional contact in the maintainer's profile to arrange a private channel. Never disclose a live secret publicly.

If a secret is committed, revoke or rotate it at the issuing service. Deleting a file or adding it to .gitignore does not invalidate it or remove history.
